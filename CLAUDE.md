## Project

HackTrack EU (formerly "Euro Hackathons") is a Next.js 16 (App Router) site that aggregates hackathons happening across Europe. Data is scraped from external sources, stored in Supabase, exposed via a REST API and a filterable web UI, and pushed out through Discord/Telegram/Twitter bots. The public README table is auto-regenerated by the same pipeline.

## Commands

```bash
npm run dev              # start dev server (next dev --turbopack)
npm run build             # prebuild runs `format` + `knip`, then `next build --turbopack`
npm run start              # run production build
npm run lint                # next lint
npm run format              # prettier --write .
npm run knip                 # find unused files/exports/deps
npm run sitemap               # regenerate sitemap (also runs postbuild)
npm run update-themes          # regenerate constants/additional-themes.js, then format
npm run update                  # bump deps with npm-check-updates, reinstall, update-themes
npm run reinstall                # wipe node_modules/lockfile/.next and reinstall
```

There is no test runner configured in this repo (no Jest/Vitest/Playwright) — do not assume `npm test` exists. Correctness is validated via `tsc`/`next build` (type checking), `eslint`, and `knip` (dead code).

To exercise the update pipeline locally, call `POST /api/update` with header `Authorization: Bearer $CRON_SECRET`; add `x-test-mode: true` to skip notifications and the README/GitHub write. This fork has no access to the original repo owner's Supabase project — point `NEXT_PUBLIC_SUPABASE_URL`/keys at your own Supabase project or local instance instead (see the roadmap section below).

## Architecture

### Data pipeline (`app/api/update/route.ts`)

This route is the heart of the system, triggered by an external cron job. It is a linear pipeline, and each stage is wrapped so a failure in one stage doesn't abort the rest:

1. Reset `is_new` flags on all rows in Supabase.
2. Run each enabled parser (`lib/parsers/*`, all extending `BaseParser` from `lib/parsers/base-parser.ts`) to fetch `ParsedHackathon[]`. Sources are toggled individually via the `sourceResults` map in the route — LabLab is currently disabled (Cloudflare-protected, can't be queried server-side reliably); Luma is the active source.
3. Deduplicate by `name + date_start` composite key.
4. Enhance locations via `LocationEnhancementService` (geocoding), reusing already-known URLs from Supabase to avoid redundant geocoding calls.
5. Diff against existing `url`s in Supabase and batch-insert only new rows.
6. Call the `update_hackathon_statuses` Postgres RPC to recompute upcoming/past status.
7. If new hackathons were inserted (and not in test mode), fan out notifications to Discord/Telegram/Twitter bots (`lib/bots/*`) via `Promise.allSettled`, then mark rows `notified: true` if at least one channel succeeded.
8. If data changed (and not in test mode), regenerate `README.md` via `ReadmeUpdater` (`lib/services/readme-updater.ts`) and commit it straight to GitHub through the Octokit REST API (not a local git operation).

The route always returns 200/500 with a detailed JSON diagnostic body (per-source results, per-stage errors, memory usage) rather than throwing — treat every stage's error field as independent, non-fatal state when reading or extending this handler.

### Data model

- `types/database.ts` — Supabase-generated types (source of truth for table shape).
- `types/hackathon.ts` — `Hackathon = Database["public"]["Tables"]["hackathons"]["Row"]`.
- Several Supabase calls in `route.ts` carry `@ts-expect-error` because the generated types don't cover `update`/`insert` shapes precisely — this is expected, not a bug to silently "fix" by loosening types elsewhere.
- `lib/supabase.ts` exports two clients: `supabase` (anon key, safe for client-exposed reads) and `supabaseAdmin` (service role key, server-only — used in API routes and scripts).

### Parsers

New sources implement `BaseParser` (`lib/parsers/base-parser.ts`), returning `ParsedHackathon[]`. The base class provides `formatDate` (tolerant of `"N/A"` and `Z`-suffixed strings) and `extractTopics` (delegates to `defaultTopicExtractor` in `lib/topic-extractor`, standardizing against `HackathonTopic` from `lib/constants/topics.ts`). Wire a new parser into the pipeline by adding it to `sourceResults` and the parse block in `app/api/update/route.ts`.

### Frontend

- App Router pages under `app/` (`app/docs`, `app/privacy`, `app/terms`, root listing page).
- `app/api/hackathons/route.ts` is the public read API (`GET /api/hackathons?status=upcoming|past`), separate from the write-only `app/api/update` cron endpoint.
- `contexts/filter-context.tsx` holds hackathon filter state (status/location/topics/dates); `contexts/translation-context.tsx` drives i18n.
- `i18n/*.json` — one JSON file per locale (en, it, de, es, fr, nl, pl, pt, ro, sv). Keep keys in sync across all files when adding new UI strings.
- UI components in `components/ui` follow shadcn/ui conventions (Radix primitives + `class-variance-authority` + `tailwind-merge`).

### Notifications

`lib/bots/{discord,telegram,twitter}-bot.ts` each expose a `notifyNewHackathons(hackathons)` method, invoked together via `Promise.allSettled` so one platform's failure/missing credentials doesn't block the others.

### Environment variables

Required at runtime (see `.env.example`): `NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_ANON_KEY`, `SUPABASE_SERVICE_ROLE_KEY`, `OPENAPI_GEOCODING_KEY`, `DISCORD_WEBHOOK_URL`, `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHANNEL_ID`, `TWITTER_API_KEY`/`TWITTER_API_SECRET`/`TWITTER_ACCESS_TOKEN`/`TWITTER_ACCESS_TOKEN_SECRET`, `GITHUB_TOKEN`, `CRON_SECRET`.

### Path aliases

`@/*` maps to the repo root (see `tsconfig.json`), e.g. `@/lib/supabase`, `@/types/hackathon`.
